# Protocol 13 host implementation plan

Estimates are changed source and test lines, excluding generated schema.
Implement against the [draft contract](README.md) without changing served
protocol 12. Land no partial v13 emitter. The product owns the v13
projection; neither JSONL v1 nor a runner, gateway, export or store version
changes merely because the client protocol changes. Items 8 and 9 are out
of scope.

| Item | Host changes and ownership | Offline acceptance and budget |
| --- | --- | --- |
| **1: newest-first and older history** | Add a read-only range projection in `bin/plakd/src/store/views.rs` (or a sibling `transcript_history.rs`) over `transcript_rows`, product notices/imports and authoritative turn boundaries. Capture session/line-head binding, prune fence, page and preceding totals in one read snapshot. Seek backward by a stable ordinal, never an offset into an appendable row set. Wire through `bin/plakd/src/host/sessions/` and `crates/hosting/hosted/src/host_service/wire/{host.rs,served.rs}`. Count UTF-8 row-body bytes, not encoded bytes; use the actual encoded byte bound to pack frames, normally targeting 256 KiB for a logical page. A newer appended turn must not change the meaning of an old cursor. | **500–850**. Store read work required; prefer existing durable facts, add a derived turn-boundary/prune index only if the indexed query cannot be bounded without it. No runner change. Cover live, dormant, archived and child scopes where addressable, append and same-key re-exec, prune and line-head rebind, sparse ordinals/imports, empty history, multibyte truncation/row read, oversize whole turns, ordered parts, and measured first-page reads on a large transcript. |
| **2: retained revisions** | Extend `crates/hosting/hosted/src/host_service/retained.rs`, `attachment.rs` and `wire/{host.rs,served.rs}`. Retain a bounded set of exact viewport revisions and a gap-free patch chain (or one equivalent atomic patch); validate generation, scope, line head, viewport token and starting revision before declaring replay. If any check fails, use item 1. Freeze the replay endpoint before exposing it; serialize replay ahead of new patches and do not hold the reader slot while paging. | **240–400**. Process-local only; no runner or persisted revision. Cover known replay, too old, wrong node/line/viewport, prune, queue eviction, concurrent appends and same-key re-exec falling back to the first page, with no stale patch after a reset. |
| **3: preview and cost** | Extend `bin/plakd/src/host/sessions/directory.rs` and `bin/plakd/src/store/{directory_projection.rs,views.rs}`. Reuse measured usage/price inputs from `crates/hosting/hosted/src/runtime/usage.rs`; aggregate nonduplicate root and descendant terminal operations in integer USD micro-units with checked arithmetic. Unknown price/usage cannot become zero; tree coverage needs known attribution, retention and reporting. Do not scan each transcript or whole-home usage on every directory tick. | **280–500**. Store read/projection required; add cached derived columns or an index only if necessary for the directory bound. No runner transport change. Cover fallback, redaction/markup/control text, UTF-8 boundary, zero vs unknown, duplicate prevention, mixed partial coverage, pruned/remote/dormant evidence and watch invalidation. |
| **4: typed attention** | Replace `needs_operator` in the client projection at `crates/hosting/hosted/src/host_service/{attention.rs,wire/host.rs}` and in `bin/plakd/src/host/sessions/directory.rs`. Gather active reasons from `crates/hosting/hosted/src/runtime/operator_attention.rs`, the parked/durable facts in `bin/plakd/src/store/{attention.rs,directory_projection.rs,views.rs}` and the runner directory verdict. Publish each reason once per relevant account or category with its occurrence's first observed host UTC time; preserve it through repeated watches, clear it on resolution, and treat upgrade interruption as quiet. | **300–500**. Store readers needed for dormant facts. Reuse source occurrence timestamps where present; if missing, scope an additive timestamp projection separately rather than stamping every read with now. No runner transport change. Cover concurrent causes, stable/reopened vs cleared causes, account-only usage-limit detail, quiet interruption and parity between list/watch. |
| **5: reconcile subphase** | In `bin/plakd/src/host/sessions/runner_views.rs`, map existing `ProbePhase::Reconcile*` variants to the exact six subphases, not detail strings. Preserve the mapping through options progress, directory status and placement refusals in `crates/hosting/hosted/src/host_service/wire/host.rs`. | **80–150**. No runner or store change: runner-side phase facts exist. Inject all six phases plus timeout, recovery/ready and unconfigured runner; assert the same typed phase in all three client paths. |
| **6: running counts** | Change the v13 aggregation in `crates/hosting/hosted/src/host_service/attention.rs` / directory enrichment in `wire/host.rs` and keep `bin/plakd/src/host/sessions/directory.rs` as the dormant/default source. Count only pending/running/sealing descendants, separately count held descendants, and count running/stopping process views, with no root count or duplicate across publications. | **70–130**. No store or runner transport changes; use existing hosted tree/process views. Test all status edges, release, peer process, parking and held-to-resumed transitions. |
| **7a: typed money** | In `crates/hosting/hosted/src/subscription_usage.rs` and `subscription_usage/openrouter.rs` convert provider-reported amounts at the projection boundary, before formatting, then publish through `bin/plakd/src/host/console/usage.rs` and the Usage Limits observation. Report only what the current authenticated source knows, including reported zero or negative balances; do not scrape display strings, infer credits from an allowance, or add management credentials. | **170–320**. No store/runner changes. Test integer conversion and rounding, optional values vs measured zero, provider cap/used/remaining and parity between console and attached usage. |
| **7b: VCS version refusal** | At the trusted Changes version check in `crates/core/tools/src/environment/backend/changes/{git.rs,repository.rs,types.rs}`, carry the observed version and actual requirement through `bin/plakd/src/host/console/files/changes.rs`. Only a known mismatch gets this refusal; unknown VCS/unsupported operations remain separate. The paired Changes execution authority must report its own version, never the host's. | **130–230**. No store change. The current paired reply carries no version evidence. Extending the closed Changes reply in `crates/core/tools/src/environment/backend/runner/wire.rs` requires a coordinated runner protocol bump and a new Changes pin; do not rewrite an existing runner pin. Verify local/paired parity, malformed/unavailable versions and existing read safeguards. |
| **10: per-blob refusal** | In `crates/hosting/host-protocol/src/wire.rs` and `crates/hosting/hosted/src/host_service/wire.rs`, report the actual rejected or discarded ids from the bounded assembler (including any prior staged blobs destroyed by an overflow). Send one definitely-not-admitted outcome per affected id; keep intent admission distinct. Never attribute an unidentifiable malformed frame or lost transport to an arbitrary blob. | **140–240**. No store or runner changes. Test out-of-order/duplicate parts, oversized and aggregate-cap rejection, unaffected siblings, intent refusal, and loss after admission with no inferred replay permission. |
| **11: lifecycle** | Feed actual drain/start deadlines into `bin/plakd/src/host/{lifecycle.rs,upgrade.rs,reexec.rs}`. Startup after Welcome can publish `starting`; before Welcome keep the bridge's typed startup refusal. Do not advertise Running/Ready ahead of serving readiness or carry a previous generation's deadline into the new process. | **140–240**. No store or runner changes. | **A: keyed streams and baselines** | Allocate stable live assistant/reasoning keys and byte offsets in `crates/hosting/hosted/src/runtime/projection/transcript/{live.rs,repair.rs}` and publish through `runtime/projection/transcript.rs`, `host_service/{retained.rs,attachment.rs}` and `wire/served.rs`. Publish with a fence so *every* root patch/baseline covers all assistant bytes already emitted for rows it reconciles; no late append belongs to a superseded baseline. If an assistant body exceeds its maximum framed representation, cap its streamed prefix before emission, preserve it in the baseline, and expose the omitted suffix through item 1. Keep patch/replay revision validation and the in-process/JSONL observation behavior separate. | **350–620**. No runner protocol or canonical store change; reuse projected row identity and item 1's read path. Test dropped/duplicate/out-of-order deltas, reasoning and multibyte offsets, cumulative live text at every patch/baseline, terminal row transition, attachment while paging, multiple observers, oversized live row, and addressed single-row repair. |
| **B: attachment status** | Meter counters and queue gauges in `crates/hosting/hosted/src/host_service/{attachment.rs,queue.rs}` and `wire/{host.rs,served.rs,paced.rs}`. Count evicted deltas, skipped patches, sent baselines and sequence discontinuities at defined producer/writer seams. Report changes at most once per 10 seconds (since the last periodic report) and answer explicit requests even when idle. Status frames have no transcript sequence, consume bounded control capacity, and do not count themselves toward the telemetry wakeup. | **150–260**. No store or runner change. Force queue eviction, a skipped patch, a baseline and a sender-visible sequence gap; check monotonic counters, gauges returning to zero, no idle flood, prompt explicit reply and per-attachment isolation. |

Dispatch in this order:

1. Start item 1's store/authority read seam and A's projector work in
   parallel, with disjoint files; agree the row key and body-byte accounting
   API before integrating. Finish the viewport framing and A's publication
   fence together. Item 2 follows that fence; B follows the attachment
   paging and replay seams so it meters actual behavior.
2. Parallelize the directory work as one worker for 3 and 4's store readers
   and cache, another for 5 and 6's projections with a single owner for
   shared directory files. Join only after list/watch parity is proven.
   Items 7a, 7b, 10 and 11 are separately dispatchable, but serialize edits
   to the generic wire dispatcher. Coordinate any runner change independently
   of the client version and stage the matched runner before using it.
3. Integrate at the staging switch, not by accepting a mix on one listener.
   Replace the served frame boundary and exact Hello pair in
   `crates/hosting/host-protocol/src/wire.rs`,
   `crates/hosting/hosted/src/host_service/wire.rs`,
   `bin/plakd/src/host/{socket.rs,bridge.rs}`, stdio and web transports.
   Move unchanged cases onto the shared DTO declarations, not a second
   running serializer. Remove the draft CLI selector and have the normal
   schema and build-info paths publish v13 with the actual binary identity.
   Repin the serving schema only if reviewed definitions changed. Port
   schema/golden/CLI assertions and update the served protocol spec and
   integration guide in that switch. Keep protocol 12 on the unchanged
   production tree until the coordinated cut.

Stage the complete candidate via the paired deploy path in an isolated
environment with the exact-schema web and executable artifacts. Activate
them together after the new host is ready, then verify that Hello 12 is
refused and Hello 13 gets Welcome 13 through each transport. Rehearse
prune/rebind and same-key restart, large-history first paint/scroll,
mid-stream reconnect and queue loss, blob refusal and console/runner
parity. Check staging schema/manifest identity, first paint and ping latency
under load, and the intake and activation boundaries before production.
Protocol 13 is not enabled by a setting on the definitions-only build.
