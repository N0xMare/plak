# Integrating with Plak

Choose the boundary that fits your application. There is one agent runtime,
whether you embed it or drive the product out of process.

| Surface | Use it for |
| --- | --- |
| In-process `plakous` | A Rust application that owns construction, tools, credentials and persistence. Start with [Embedding](embedding.md). |
| `plak agent --wire v2` | One session over a child process's stdin/stdout; diagnostics stay on stderr. |
| `plak host` | A long-lived session directory over a private same-user Unix socket, `plak host connect --stdio`, or the authenticated WebSocket endpoint. |
| `plak run` | Non-interactive jobs: prompt in, final answer on stdout, progress on stderr, and a process exit status. |
| `plak runner` | Paired execution placement for an existing host, not a frontend API or another agent loop. |

The [CLI reference](cli.md) covers flags. The normative contracts are
[wire v2](../spec/02-plak-product.md#44-wire-v2),
[host lifecycle](../spec/02-plak-product.md#46-plak-host) and
[exit classes](../spec/02-plak-product.md#33-exit-codes). The host and runner
protocols are distinct. Do not use JSONL v1 as a new integration boundary.

## Schema and exact versions

```sh
plak wire schema > wire-schema.json
plak agent --wire v2 --account codex --model gpt-5.6-luna --effort low
plak host connect --stdio
```

The last two commands start different wire transports; choose one. The stdio
bridge discovers the current host; starting a missing host requires its
explicit `--auto-start` option. Bare `plak` does not auto-start a host.

`plak wire schema` is supported in ordinary release builds. Release assets
include `plak-<version>-<triple>-wire-schema.json`, generated by that target's
binary and covered by `SHA256SUMS` and build provenance. Prefer the schema
printed by the actual binary when integrating a source build.

The `v2` grammar currently carries `proto: 9`. Versions match exactly, with no
negotiation or downgrade. Check `wire_version` and `binary_id` in the schema;
on a mismatch, update the client for the binary you intend to use rather than
retrying another version. A socket, the stdio bridge, and WebSocket all carry
the same JSON frames. WebSocket authentication, origin checks and message
boundaries are described in spec 02; the example below uses only a trusted
same-user control socket, not a web endpoint.

## Hello, find a session, attach

Start `plak host` in a separate terminal. It prints its control socket on
stderr. Create a session using the TUI or an existing host client, then use
its full session id. A directory host's welcome names no single session.

Each frame is one newline-terminated JSON object on a socket or stdio stream.
Send hello first:

```json
{"frame":"hello","proto":9,"binary_id":"python-example","caps":[]}
```

The host replies `welcome` with its matching `proto`, binary id, generation,
capabilities and principal-specific extension. List sessions:

```json
{"frame":"request","id":1,"op":{"op":"list_sessions","include_archived":false}}
```

The response with `id: 1` has `outcome.ok.answer: "sessions"` and `rows`.
Find the desired session and copy its `node` address **as returned**; a root's
agent id is not necessarily the literal `root`. Attach that address:

```json
{"frame":"request","id":2,"op":{"op":"attach","node":{"tree_id":"<tree-id>","agent_id":"<root-agent-id>"}}}
```

The response with `id: 2` answers `attached` and names an attachment. Snapshot
pages and events follow; a snapshot's `last: true` completes that revision.
Keep request ids distinct and correlate responses by id while reading other
frames. Send `{"frame":"bye"}` before closing. Reconnect means a new attach,
not replaying requests or inferring lost model/tool outcomes.

The [stdlib-only Python reference client](../../tools/examples/host_client.py)
executes this read-only sequence and prints the received frames through the
initial snapshot. It sends no prompt or tool request. Run it from a checkout:

```sh
python3 tools/examples/host_client.py --socket /path/from/host.sock --session FULL_SESSION_UUID
```

It assumes the named socket is a trusted same-user host. It deliberately omits
discovery, authentication, reconnect/recovery, blob assembly and presentation
rendering; it is a protocol example, not an SDK. `just steps tooling` runs the
client and this transcript against an isolated, offline-scripted real host.

## A bounded CI job

Supply an API credential through the CI system's secret environment, not an
argument or a checked-in file. Choose an exact model id available to that
account; `PLAK_MODEL` below is an example caller-owned variable.

```sh
: "${OPENAI_API_KEY:?set this through the CI secret environment}"
: "${PLAK_MODEL:?set an exact OpenAI API model id}"
export PLAK_HOME="$(mktemp -d)"
trap 'rm -rf -- "$PLAK_HOME"' EXIT
if plak run --account openai --model "$PLAK_MODEL" --effort low \
    --max-turns 5 --timeout 300 -- 'Run the tests and explain any failures.' > answer.txt; then
  status=0
else
  status=$?
fi
case "$status" in
  0) echo 'completed' ;;
  2) echo 'invalid invocation or selection' >&2 ;;
  3) echo 'credential/admission failure' >&2 ;;
  4|130) echo 'interrupted or shutdown did not join' >&2 ;;
  5) echo 'agent/product failure or recovery required' >&2 ;;
  6) echo 'turn/time budget reached' >&2 ;;
  7) echo 'session held by another live process' >&2 ;;
  *) echo 'configuration or other failure' >&2 ;;
esac
exit "$status"
```

Use `--effort` only if the chosen model requires it. `run` has full host tool
authority and no approval gates; use a disposable CI workspace with the
authority you intend to grant it. Its success means the agent completed, not
that a separate test command necessarily passed; enforce required checks in
your surrounding job. See the CLI reference for output and continuation rules.

## Service setup

[Host service setup](host-service.md) includes the Linux systemd user-unit
example. `plak host install` writes that unit and prints the commands to enable
it, configure lingering and inspect logs; it does not start or enable it.
The installer currently refuses macOS: it does not yet write a launchd plist.
On macOS, run `plak host` directly; do not assume Linux service commands apply.
