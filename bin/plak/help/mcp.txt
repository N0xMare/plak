plak mcp — MCP servers a template can list as mcp:<id>

USAGE:
  plak mcp add <id> [options] -- <command> [args...]        (stdio)
  plak mcp add <id> --url <url> [options]                   (http)
  plak mcp list
  plak mcp show <id>
  plak mcp test <id>
  plak mcp remove <id> [--scope user|project] [--force]
  plak mcp enable <id> --template <name> [--tool <tool>]...
  plak mcp disable <id> --template <name>

ADD OPTIONS:
  --scope user|project      Which config.toml gets the table (default user)
  --env KEY=VALUE           Literal environment (stdio; repeatable)
  --secret-env KEY=SECRET_NAME     Environment from a stored secret (stdio; repeatable)
  --bearer-secret SECRET_NAME      Authorization: Bearer from a stored secret (http)
  --header NAME=VALUE       Literal header (http; repeatable)
  --header-secret NAME=SECRET_NAME Header from a stored secret (http; repeatable)
  --tools a,b               Server allowlist; mcp:<id> means exactly these
  --startup-seconds N       Start and list budget (1..=120, default 20)
  --call-seconds N          Per-call ceiling (1..=3600, default 120)
  --replace                 Overwrite an existing [mcp_servers.<id>]

  add writes [mcp_servers.<id>] into config.toml, keeping the rest of the
  file, and refuses anything a config load would refuse. Secrets are named,
  never given: store each with `plak secret set <name>`.
  list and show print transport, scope, the templates that enable a server
  and any secret it names that is not stored.
  test starts or connects to the server the way a session does, lists the
  tools a template would bind and the ones left out with the reason, and
  exits non-zero with the cause when the server fails. It calls no model.
  enable and disable edit only that template file's tools array (mcp:<id>,
  or mcp:<id>/<tool> per --tool). New sessions pick the change up; existing
  sessions keep the tools they froze.
  remove refuses while a template would be left listing what no layer
  serves; --force also removes those template entries, checking every file
  first. Every edit is checked against the home configuration alone and with
  the trusted project over it; only the home's templates and the current
  trusted project's templates are checked.
